# صيدليتي — نظام إدارة مخزن صيدلية

نظام ويب متكامل، عربي بالكامل (RTL)، متجاوب مع الهاتف والتابلت والكمبيوتر، لإدارة مخزون صيدلية من لحظة دخول الدواء حتى خروجه، مع مسح باركود/QR بالكاميرا أو بجهاز USB، عمل دون اتصال (PWA)، ومزامنة البيانات مع Google Sheets عبر Google Apps Script.

## هيكل المشروع

```
pharmacy-system/
├── index.html              نقطة الدخول الوحيدة (SPA)
├── manifest.json           إعدادات PWA (تثبيت كتطبيق)
├── sw.js                   Service Worker (عمل دون اتصال)
├── css/
│   └── style.css           كل التنسيقات (فاتح/داكن، متجاوب)
├── js/
│   ├── config.js           رابط API والإعدادات العامة  ← عدّل هذا الملف أولاً
│   ├── db.js                طبقة IndexedDB (تخزين محلي + قائمة انتظار المزامنة)
│   ├── api.js                طبقة الاتصال بـ Google Apps Script
│   ├── auth.js               تسجيل الدخول والصلاحيات
│   ├── scanner.js            مسح الباركود/QR (كاميرا + قارئ USB)
│   ├── router.js             التوجيه بين الصفحات
│   ├── app.js                تشغيل التطبيق، القائمة الجانبية، الإشعارات
│   └── pages/                كل صفحة في ملف مستقل
│       ├── common.js         أدوات مشتركة (تنسيق، تصدير، طباعة)
│       ├── dashboard.js      لوحة التحكم
│       ├── medicines.js      إدارة الأدوية
│       ├── stockIn.js        إدخال المخزون
│       ├── stockOut.js       إخراج المخزون (FEFO)
│       ├── inventory.js      عرض المخزون والدفعات
│       ├── inventoryCount.js الجرد الفعلي
│       ├── suppliers.js      الموردون
│       ├── reports.js        التقارير (CSV/طباعة)
```

## خطوات التشغيل

1. **الخادم أولاً:** اتبع `apps-script/SETUP.md` لإنشاء Google Sheet ونشر Apps Script والحصول على رابط Web App.
2. **الموقع:** ضع الرابط في `js/config.js` (`API_URL`).
3. **الاستضافة:** ارفع مجلد المشروع كما هو على أي استضافة ملفات ثابتة (GitHub Pages، Netlify، Vercel، أو حتى فتحه مباشرة عبر خادم محلي بسيط). لا حاجة لأي Backend إضافي — كل شيء عبر Google Sheets.
4. **افتح الموقع، سجّل الدخول بالحساب الافتراضي:**
   - اسم المستخدم: `admin`
   - كلمة المرور: `admin123`
   - **غيّرها فوراً** من الإعدادات > إدارة المستخدمين.

> ملاحظة: لتشغيله محلياً للتجربة، لا يكفي فتح `index.html` كملف مباشرة (بروتوكول `file://`) لأن Service Worker وبعض الميزات تتطلب خادم HTTP. استخدم أي خادم بسيط، مثلاً:
> `npx serve .` أو `python -m http.server 8000` من داخل مجلد المشروع.

## الأدوار والصلاحيات

| الدور | الصلاحيات |
|---|---|
| مدير النظام (admin) | كل الصلاحيات: إدارة الأدوية، المستخدمين، سجل العمليات، التقارير، الإعدادات |
| موظف مخزن (warehouse) | إدارة الأدوية، إدخال/إخراج المخزون، الجرد، التقارير |
| صيدلي/مبيعات (sales) | عرض الأدوية، إخراج المخزون، التقارير |

## الميزات الأساسية المطبَّقة

- تسجيل دخول وصلاحيات متعددة المستويات + سجل عمليات كامل (Audit Log).
- لوحة تحكم بإحصائيات حية (كميات، مخزون منخفض، صلاحيات قريبة/منتهية، قيمة المخزون، أكثر/أقل الأدوية حركة).
- إدارة كاملة للأدوية (إضافة/تعديل/أرشفة) مع بحث ذكي فوري.
- إدخال وإخراج مخزون مع مسح بالكاميرا (خلفية الهاتف) ودعم قارئ باركود USB يعمل كلوحة مفاتيح.
- نظام **FEFO** (الأقرب انتهاءً أولاً) تلقائي عند الإخراج، مع منع إخراج كمية أكبر من المتاح.
- إدارة الدفعات (Batches) وتواريخ الصلاحية لكل تشغيلة.
- جدول مخزون شامل بفلاتر وحالات لونية (جيد/منخفض/نفد/قريب الانتهاء/منتهي).
- جرد فعلي مع حساب الفروقات وتحديث المخزون فوراً.
- إدارة الموردين.
- تقارير متعددة قابلة للتصدير CSV والطباعة المباشرة.
- عمل دون اتصال (PWA): تخزين محلي عبر IndexedDB، قائمة انتظار للعمليات، ومزامنة تلقائية عند عودة الاتصال.
- نسخ احتياطي/استيراد محلي للبيانات (JSON).
- وضع داكن، تصميم متجاوب بالكامل مع الهاتف والتابلت، وقابلية التثبيت كتطبيق (PWA).

## للتطوير المستقبلي

الكود منظم بحيث يسهل عليك أو على أي مطور إضافة:
- دعم أكثر من مخزن ونقل الكميات بينها (الدالة `transferStock_` في `Code.gs` جاهزة كنقطة انطلاق).
- طباعة ملصقات باركود/QR فعلية (يمكن إضافة مكتبة مثل `jsbarcode` أو `qrcode.js`).
- إشعارات Push حقيقية (تحتاج خدمة إضافية مثل Firebase Cloud Messaging).
- ربط مصادقة أقوى (OAuth) بدل اسم مستخدم/كلمة مرور بسيطة.

## أمان البيانات

- كل الكتابة/التعديل/الحذف تمر عبر `Code.gs` فقط — لا اتصال مباشر من المتصفح بالشيت.
- الحذف "منطقي" (Soft Delete/أرشفة) دائماً؛ لا تُفقد بيانات نهائياً.
- كلمات المرور مخزَّنة كـ SHA-256 hash.
- كل عملية مسجَّلة في `ActivityLog` مع اسم المستخدم والتاريخ والتفاصيل.
